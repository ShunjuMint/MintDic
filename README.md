## MintDic
創作の為に春秋みんとが作る人工言語の為の辞書サイトで、ほとんどvibe codingです
## 例文を独立管理する

例文は `site/data/sample sentence/` に登録します。`sentences.json` にまとめることも、`日常.json` など複数のJSONへ分けることもできます。各ファイルの最上位は配列です。下層フォルダは作りません。

```json
[
  {"id": "s-001", "text": "人工言語の例文", "translation": "日本語訳"},
  {"id": "s-002", "text": "別の例文", "translation": "別の日本語訳"}
]
```

語彙の `examples` には、その例文IDを並べます。

```json
"examples": ["s-001", "s-002"]
```

単語の詳細画面に、この順番で本文と訳が表示されます。同じ例文を複数の単語から参照できます。本文・訳を例文ファイル側で変更すると、次回公開時にすべての参照元へ反映されます。例文を付けない場合は `[]` または項目の省略で構いません。

例文IDは半角英数字・ハイフン・アンダースコアを使用し、例文フォルダ全体で一意にしてください。本文と訳は必須です。存在しないID、重複した例文ID、同じ単語内の重複参照は検査エラーになります。参照中の例文を削除する場合は、語彙側のIDも取り除いてください。

ビルド時にID参照を解決し、公開用 `dist/data/words.json` に本文と訳を展開します。元の語彙JSONは書き換えません。`npm test` と `npm run build` で確認できます。

従来の `examples: [{"text": "…", "translation": "…"}]` という直接記入形式は使用しません。手元にその形式の例文がある場合は、本文・訳を例文フォルダへ移してIDを付け、語彙側をID配列へ置き換えてください。今回確認したGitHubの語彙には例文本文はありませんでした。

辞書編集アプリも、語彙の `examples` をID配列として読み書きし、例文フォルダを扱う対応版が必要です。この変更はサイト側の対応です。
